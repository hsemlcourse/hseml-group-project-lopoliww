# CP1 — Предсказание спроса на онлайн-курсы

## 1. Постановка задачи

Задача проекта — регрессия: предсказать спрос на онлайн-курс по публичным характеристикам курса и его учебной структуры. В качестве таргета используется `learners_count`, то есть число учеников на курсе Stepik.

Основная метрика — RMSE по `log1p(learners_count)`. Я выбрал логарифмированный таргет, потому что распределение числа учеников обычно сильно скошено: много маленьких курсов и немного очень популярных. Ошибка в лог-шкале меньше наказывается за абсолютные различия между крупными курсами и лучше отражает относительную ошибку.

## 2. Поиск и описание данных

Источник данных — публичный REST API Stepik. Для CP1 реализован самостоятельный парсинг реальных данных. Используются эндпоинты `courses`, `sections`, `units`, `lessons`, `steps`.

Единица наблюдения — учебный шаг курса. Одна строка соответствует одному step и обогащается признаками родительского курса, секции, юнита и урока. Такой формат позволяет получить 10 000+ реальных строк без синтетического увеличения датасета.

Сырые данные сохраняются в `data/raw/stepik_course_steps.jsonl`, обработанные — в `data/processed/stepik_course_steps_processed.csv`.

## 3. Обработка и подготовка данных

В `src/preprocessing.py` реализованы следующие шаги:

- чтение JSONL;
- нормализация вложенного JSON;
- удаление дублей по `course_id`, `section_id`, `unit_id`, `lesson_id`, `step_id`;
- приведение числовых полей к числам;
- создание `target_log_learners_count`;
- создание текстовых фичей: длина названия, описания, названия урока, количество слов;
- создание структурных фичей: позиция секции, позиция юнита, позиция шага, число шагов в уроке;
- создание бинарных признаков: платность, публичность, архивность, наличие сертификата, наличие видео;
- group split на `train`/`val`/`test` по `course_id`.

Group split нужен для защиты от dataleak. У всех шагов одного курса одинаковый таргет `learners_count`, поэтому шаги одного курса не должны одновременно попадать в train и test.

## 4. Baseline-модель

В `src/modeling.py` есть два baseline-подхода:

- `dummy_median` — константная модель, предсказывает медиану таргета;
- `ridge_alpha_1` / `ridge_alpha_10` — простая линейная модель с регуляризацией.

Числовые признаки проходят median-imputation и scaling, категориальные — most-frequent imputation и one-hot encoding.

## 5. Эксперименты CP1

В CP1 добавлены несколько моделей из коробки:

| Гипотеза | Как проверяется | Где результат |
|---|---|---|
| Медиана даёт минимальный sanity-check | `DummyRegressor(strategy="median")` | `models/metrics.csv` |
| Линейная зависимость уже может дать сигнал | `Ridge` с разными alpha | `models/metrics.csv` |
| Нелинейные зависимости важны | `RandomForestRegressor` | `models/metrics.csv` |
| Случайные деревья могут быть устойчивее леса | `ExtraTreesRegressor` | `models/metrics.csv` |
| Бустинг лучше работает с табличными признаками | `HistGradientBoostingRegressor` | `models/metrics.csv` |

Лучшая модель выбирается по минимальному RMSE на validation split. После выбора лучшая модель дополнительно оценивается на test split и сохраняется в `models/best_model.joblib`.

## 6. Воспроизводимость

Для воспроизводимости сделано:

- fixed seed `42` в split и моделях;
- зависимости зафиксированы в `requirements.txt`;
- запуск парсинга, обработки и моделирования описан в `README.md`;
- тесты находятся в `tests/test.py`;
- линтер запускается командой `ruff check src tests`.

## 7. Что сдаётся в CP1

CP1 закрывает:

- самостоятельный парсинг реальных данных;
- подготовку датасета 10 000+ строк при запуске step-level парсинга;
- очистку, feature engineering и split без утечки;
- baseline и несколько моделей-экспериментов;
- воспроизводимый запуск и тесты.
